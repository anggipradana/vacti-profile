How it works

The engagement lifecycle, end to end

Every engagement follows the same disciplined path: scoped, tested autonomously, proven by an oracle, and delivered as evidence. A self-hosted control plane holds the data and the methodology; a fleet of engines does the testing over an outbound-only link.

  1. 01

    Scope the engagement

    Define in-scope targets, per-role test accounts, and context, then pick a vertical and the run knobs: stealth for WAF-fronted targets, a time budget, and prober depth.

  2. 02

    Recon and crawl

    The surface is mapped end to end: the recon pipeline, route and JS-bundle extraction, and live proxy flow capture build a deterministic inventory of every route and parameter.

  3. 03

    Autonomous orchestration

    An agent swarm drives a real browser and tool arsenal through the proxy, testing every route against every applicable class at full depth and creating candidate findings.

  4. 04

    Oracle-gated verification

    A deterministic prober confirms the baseline exploitation floor, then a QA-verifier refutes and reproduces each candidate step by step before it is ever accepted.

  5. 05

    Evidence capture

    Every finding ships with verbatim request and response bytes re-fetched from the proxy, browser screenshots, and a re-executed proof, never text typed by the model.

  6. 06

    Report and retest

    Deliver a bilingual PDF with SARIF and XLSX exports, a re-importable proxy project, and draft submissions. Re-queue any engagement to continue, deepen, or re-validate.

The platform

Four pillars, one console, one data plane

VACTI is not a single scanner. It joins autonomous penetration testing, vulnerability assessment and threat intelligence, bug-bounty and CTF workflows, and mobile and desktop testing under one control plane and one shared data model.

AI penetration testing

An autonomous agent swarm that tests like an operator, then proves every finding before it reaches your triage.

  • A producer swarm drives a real browser and tool arsenal through a proxy across web, API, source white-box, and CVE targets at full depth.
  • A deterministic prober confirms the baseline injection and service points independent of the model, so coverage is consistent run to run.
  • A QA-verifier re-tests each candidate and runs a refutation gate on critical and high findings, accepting only what it reproduces.
  • Continue, deepen, and re-validate resume an engagement exactly where the last run stopped.

Vulnerability assessment and threat intelligence

Map the surface, score the risk, and watch the exposure, from one recon pipeline and one risk model.

  • A straight recon pipeline over all-Go scanners, with per-finding CVSS, CVE, and references and an AI-enriched triage workflow.
  • Passive OSINT surface mapping with a 23-rule exposure detector for leaked keys, tokens, private keys, database URLs, and stealer credentials.
  • Breach and stealer leak lookup across datasets, treated as confidential and masked by default.
  • A unified risk score over threat feeds, leak intelligence, and sector news, identical across the dashboard and every report.

Bug bounty and CTF

Take a confirmed finding straight to a submission, or point the same engine at a flag.

  • Draft and manage HackerOne and Bugcrowd submissions, with token-less drafting built in.
  • Human-in-the-loop approval is database-locked with advisory dedup to stop duplicate submissions.
  • A flag-graded CTF engagement mixes web and infrastructure classes with dedicated CTF methodology.

Mobile and desktop

Drive the real app on a real device, then test the backend it talks to.

  • Android and iOS engagements run a managed app agent that drives the app on a paired device.
  • SSL-pinning and anti-instrumentation handling keep the session live against hardened apps.
  • Desktop thick-client and native-app assessment covers the binary and the services it calls.
  • Both reuse the authorization and IDOR probers against the backend API, so mobile findings carry the same proof.

Why VACTI

Built for teams that answer to auditors

Your methodology never leaves your control

The control plane and the engine fleet run on infrastructure you own. The knowledge corpus and skill library, the methodology itself, stay on the control plane, are fetched per engagement into memory, and are wiped after the run. The shipped engine holds the runtime, never the intellectual property.

Proven, not guessed

Every high-impact finding passes a class-specific confirmation oracle with a re-executed proof. A finding that cannot be proven is marked inconclusive and flagged for review rather than silently dropped, so model guesses never reach your report as findings.

One data plane, one risk score

VA scans, pentest findings, bug-bounty submissions, CTF challenges, leak intelligence, and threat feeds live in one schema, with a cross-engagement asset catalog and a single risk score shared across the dashboard and every report.

Evidence you can hand to an auditor

Verbatim request and response exhibits, screenshots, re-executed proofs, and exploit-flow diagrams, tagged with OWASP, CWE, and CVSS, delivered as a bilingual PDF with SARIF and XLSX exports in a formal, bank-grade report layout.

Deploy anywhere, update everywhere

The engine runs on any Linux host, whether bare metal, a virtual machine, or a container. Engines enroll with a one-time token and self-update on an idle-gated timer, so a whole fleet stays current without a manual redeploy.

Lightweight by design

The control plane is three lean services running end to end in TypeScript, with no Redis and no Celery. You get multi-project workspaces, server-side RBAC, an encrypted key vault, audit logging, and a typed REST API out of the box.

Architecture

Control plane and engine fleet, strictly separated

The control plane orchestrates and stores. The engine fleet tests. The link is one-way: each engine reaches out to pull authorized engagements and write back results. There is no inbound port on an engine.

Engines enroll once with a single-use token that is exchanged for scoped producer, verifier, and gatekeeper tokens. From then on they poll for authorized jobs and write findings and evidence back over the outbound link, routing all test traffic through the capture proxy, their sole evidence source. The methodology and knowledge corpus stay on the control plane.
