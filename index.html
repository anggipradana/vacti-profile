How it works

Three beats, one disciplined run.

Every engagement follows the same path: scoped, attacked autonomously, then proven before anything reaches your triage.

  1. 01

    Scope and recon

    Define scope and per-role test accounts. The recon pipeline maps every route and parameter into a deterministic inventory.

  2. 02

    Autonomous attack

    The swarm drives a real browser and tool arsenal through the capture proxy, against every applicable class at full depth.

  3. 03

    Oracle-gated proof

    The deterministic prober confirms, the verifier reproduces, and the evidence is re-fetched from the proxy before a finding is accepted.

Capabilities

What the engine brings to one run.

Attack, proof, and delivery in a single autonomous engagement. Each capability below maps to a real part of the engine, grouped by the job it does.

01Attack

Autonomous agent swarm

A producer pass drives a real browser and the tool arsenal through the capture proxy, creating candidate findings against every applicable class.

02Attack

Deterministic prober

Independent of the model, the prober sweeps every route, parameter, and injection class, so coverage stays consistent from one run to the next.

03Attack

Surfaces in one engine

The same methodology tests web and API, infrastructure, mobile and iOS, desktop, source review, CTF, and web3, selected per engagement.

04Attack

Active Directory and infra

Host, port, and service discovery with an nmap NSE floor, plus rootDSE-confirmed Active Directory testing steered to a dedicated tool server.

05Proof

Confirmation oracles

Each class emits a finding only when a class-specific oracle proves exploitation: sqlmap for SQL injection, a JavaScript-execution flag for XSS, an id to uid check for command injection.

06Proof

Verifier and refutation gate

A second pass re-tests every candidate, separates true from false positives, and for critical and high findings tries to disprove the result before it is accepted.

07Proof

Verbatim evidence

No finding ships without a captured request and response pair from the proxy. Model-typed bytes are demoted to a labelled reconstruction and the exact flow is re-fetched.

08Proof

False-positive tightening

Root-cause dedup, hardening consolidation, and proof-gated severity run before writeback, so the operator sees proven impact instead of a wall of raw leads.

09Delivery

Runs on infrastructure you own

The control plane orchestrates and stores. The engine fleet tests over an outbound-only link and exposes no inbound port. The methodology corpus stays on the control plane.

10Delivery

Resume and continue

Every tested cell is recorded, so a finished engagement can be re-queued to continue untested cells, deepen for new coverage, or re-validate existing findings.

11Delivery

Findings and evidence writeback

Verified findings and verbatim evidence are written back to the control plane. The whole engagement's Caido project exports as a re-importable file, alongside an analysis bundle of the run's forensics.

12Delivery

Client-VPN engagements

For targets reachable only over a customer VPN, the swarm self-connects per run across GlobalProtect, Fortinet, AnyConnect, OpenVPN, WireGuard, and IPsec, with split-tunnel routing.

Why VACTI

Built for teams that answer to auditors.

Proven, not guessed.

Every high-impact finding passes a class-specific confirmation oracle with a re-executed proof. A finding that cannot be proven is flagged for review, never shipped as a result.

One data plane, one risk score.

Vulnerability assessment, pentest findings, leak intelligence, and threat feeds share one schema and one risk score, identical across the dashboard and every report.

Your methodology stays with you.

The control plane and the engines run on your own infrastructure. The knowledge corpus lives on the control plane, is fetched per run into memory, and is wiped from the engine afterwards.

Architecture

Control plane and engine fleet, strictly separated.

The control plane orchestrates and stores. The engine fleet tests over an outbound-only link. No engine exposes an inbound port.

Engines enroll once with a single-use token, then poll for authorized jobs and write findings and evidence back over the outbound link. The methodology and knowledge corpus stay on the control plane.
