How it works

From a fresh box to verified findings

The control plane holds the data, the UI, and the methodology. The engine is the runtime that tests. The two talk over a one-way pull link, engine outbound only.

  1. 01

    Deploy the engine

    Provision a Debian or Kali box, then run the one-line installer with a single-use enrollment token. It wires the private apt repo and installs the prebuilt, minified .deb. Docker is available for non-Kali hosts. The box self-updates on an idle-gated timer.

  2. 02

    Define the engagement

    In the control-plane console, set the scope, per-role test accounts, context notes, and the run mode. Pick a vertical: web, infra, mobile and iOS, desktop, source white-box, CTF, or web3. Stealth and non-intrusive modes handle WAF- or firewall-fronted targets.

  3. 03

    Autonomous testing

    A Claude Code agent swarm tests at full power while a deterministic prober sweeps every route by parameter by injection class. Confirmation oracles gate each hit, and a QA-verifier pass re-tests, refutes, and only accepts what it reproduces.

  4. 04

    Verifiable findings

    Each finding ships with verbatim request and response bytes from Caido, screenshots, and re-executed PoCs, with an exploit-flow diagram on infrastructure findings. Deliverables include a bilingual PDF report, SARIF and XLSX exports, and a re-importable Caido project.

Capabilities

A floor of oracle-gated coverage, a ceiling of agent depth

The deterministic prober is a family of oracle-gated floors: a finding is emitted only when a class-specific oracle proves exploitation. The agent swarm then exploits, scopes impact, and chains it. These are the classes the engine covers today.

Web vulnerabilities

SQLi confirmed by sqlmap (reach broadened across first-order, second-order, and OOB modes), reflected and DOM XSS, SSRF, IDOR and BOLA, authentication bypass, LFI and RFI, upload-to-execution, SSTI, XXE, prototype pollution, GraphQL, CRLF, NoSQLi, and web-cache poisoning and deception.

API and business logic

Broken access control, BFLA, business-logic state-transition abuse, mass assignment, OAuth and JWT misconfiguration, auth-hygiene gaps (weak session id, session fixation, MFA and lockout), and a business-abuse chaining pass that links primitives into one attack path.

Mobile and desktop

Android and iOS through a managed app agent that drives the app on a paired device and reuses the web authorization and IDOR probers against the backend API. Desktop thick-client and native-app assessment, plus the server-side and API classes the client calls.

CVE and crypto hygiene

A CVE-registry client whose PoC step is bounded by a non-destructive safety ladder, an OSV novelty check on recon fingerprints, and crypto and protocol-hygiene classes: weak crypto, login password-hash KDF cost, SSH Terrapin, and cleartext credential transport.

Infrastructure

Host, port, and service discovery with an nmap NSE consistency floor, rootDSE-confirmed Active Directory testing steered to a dedicated MCP, security headers, trust-header and verb tampering, and cloud-storage exposure. Every infra finding carries a rendered exploit-flow diagram.

Evidence and proxy

Caido is the sole proxy and evidence source: the swarm's HTTP history is the attack surface, and verbatim request and response bytes are re-fetched rather than typed. A captcha solver handles Turnstile, reCAPTCHA, and hCaptcha at login.

Advantages

Why VACTI is built differently

Self-hosted by design

Your pentest data and your methodology never leave your infrastructure. The knowledge corpus and skill library are the operator's crown jewels: they live on the control plane, are fetched per engagement into memory, and are wiped after the run. The shipped .deb holds the runtime, never the IP.

Verifier-oracle discipline

Every high-impact class is gated by a class-specific confirmation oracle with a re-executed PoC. A finding that cannot be proven is marked inconclusive and flagged for review, never silently dropped and never shipped as a false positive. Quality over coverage.

Evidence-grade output

Verbatim Caido request and response exhibits, screenshots, re-executed PoCs, and exploit-flow diagrams. Anti-fabrication QA rejects authored graphics and demotes LLM-typed bytes to labelled reconstructions, then re-fetches the exact flow.

Multi-arch and fleet-ready

The engine ships for both amd64 and arm64, with a Docker image for non-Kali hosts. Boxes auto-enroll with a one-time token and self-update from the apt repo on an idle-gated timer, so a fleet stays current without a manual redeploy.

Standards-aligned reporting

Findings are OWASP-aligned and carry CVSS and CVE references, and the bilingual EN and ID reports follow a bank pentest-report reference layout, with SARIF and XLSX exports for downstream tooling.

Open-source engine

The engine is TypeScript on a Node 22 runtime, a lean single-package build, and is extensible through its skill library. The control plane is an end-to-end type-safe Nx monorepo. All of it is MIT licensed.

Architecture

Control plane and runtime, strictly separated

The control plane orchestrates and stores. The engine tests. The link is one-way: the engine reaches out to pull authorized engagements and write back results. There is no inbound port on the engine.

Engines enroll once with a one-time token that is exchanged for scoped producer, verifier, and gatekeeper tokens. From then on they poll for authorized jobs and write findings and evidence back over the outbound link. The methodology IP stays on the control plane.
